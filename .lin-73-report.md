## Open questions

1. **Calls per message.** The route counts as the message's first call, so a message sent on to the model gets 5 model calls instead of 6. Keep it, or change the `chat_use_model_call` migration so that a route does not use a model call?
2. **Unrecorded gender.** Gender comes only from `parent_role`, so gender-filtered lists can miss childless relatives. They are named in a note, not dropped. Should these questions go to the model instead? The model would then have to guess gender from names, which LIN-31 rule 1 forbids.
3. **The `wants_count` gate.** It uses confidence |2p−1| ≥ 0.5, which means p must be ≤0.25 or ≥0.75.

## PR description (ready to paste)

## What

Before a chat message goes to the model, TypeSafe Jev reads it on the server and says what kind of question it is. For the common kinds, the LIN-70 code finds the answer on the Working Record and code writes the reply, so no model call is made. Every other message goes to the model with tools, as LIN-72 built.

- **Server (`family-chat`)**: a second operation, `{ operation: 'route', messageId, message }`. It counts the message (one of the 10 a day), asks Jev five questions over `{ message }` on the pinned `jev-1.13.0` (`questionKind.ts`), and returns the answers with their confidence, plus the speaker. If TypeSafe is unset, fails, takes longer than 2.5 s, or is still busy after one short 429/529 retry, it returns no reading. The browser then goes to the model and the user sees no error. The TypeSafe call and its failure sorting are moved to `_shared/typeSafe.ts`, so `spelling-matches` uses the same code.
- **Browser (`src/lib/chatRouting.ts`)**: code answers only when all of these hold:
  - the relation is not `other`;
  - every answer the code uses is at confidence 0.5 or more (side only for grandparents, aunts/uncles and cousins; gender never for a spouse);
  - each name in the message matches exactly one Person. Names are found by code with `findPersonsByName` and never sent to Jev;
  - the code has a name for the relation.

  Replies use bold names and a bulleted list, give the total for a count, and put the blood relation first, then "also related by marriage". "mother in law" and similar phrases are read from the words of the message. A relative whose gender the tree does not record is named in a note, not silently left out.
- **Loop (`familyChat.ts`)**: the route goes first. A daily-limit refusal shows the limit line. Any other failure goes quietly to the model under the same message id, with the calls that are left.
- **Known misses fixed**:
  - plural and less common Arabic words (khalos, amtos, sitto) are in the gender and side wording;
  - a side named by a family name ("the Pharoan side") gets a new side option `family_name` and goes to the model. A cluster name that is in the tree is also read as a second name, which sends the message to the model too;
  - the gender answer is never used for a spouse.
- **Eval**: `scripts/chat-routing-eval/` holds the 46 prototype messages, with names moved to the made-up LIN-70 tree, and a script that prints the result. It is not part of `npm test`.

## Open questions

- The route is counted as the message's first call. A message that goes on to the model therefore has 5 model calls, not 6. Keeping 6 would need a change to the `chat_use_model_call` migration, or a per-message cap of 7 that a client could use by skipping the route.
